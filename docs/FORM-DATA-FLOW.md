# Куда уходят данные формы предложения

Проверено 16.11.2026 в исходном коде и браузерах Chromium/WebKit.

| Действие | Назначение данных |
| --- | --- |
| Ввод суммы, налогового формата и даты | Только поля и предпросмотр текста в текущей вкладке |
| «Скопировать для руководителя» | Системный буфер обмена после нажатия; сообщение никому не отправляется |
| Браузер запретил буфер обмена | Текст показывается в локальном поле для ручного копирования |
| Изменение условий после ручного копирования | Старое резервное поле очищается и скрывается; следующий текст строится из новых значений |
| «Сохранить PDF» | Системная печать браузера; файл сохраняется в выбранное пользователем место |
| Ссылка «Открыть таблицу Бота ФН» | Новая вкладка Google Таблиц по предоставленному адресу; значения предложения не добавляются к ссылке |

В приложении нет серверного обработчика этой формы, отправки писем, автосообщений, аналитики введённых значений или записи в localStorage/sessionStorage. Оклад по умолчанию пуст. Копирование и кнопки печати блокируются для некорректного оклада; дата проверяется как дата. Сам Python-бот на странице портфолио не запускается.

Код: [proposal.js](../proposal.js), [app.js](../app.js). Проверка: сценарий `proposal stays local, preserves approved paragraphs and rejects invalid pay before copy or PDF` в [браузерных тестах](../tests/browser/portfolio.spec.cjs). В нём проверены копирование, запрет доступа, смена значений, нулевой оклад, восстановление утверждённых абзацев, отсутствие запросов с введёнными значениями и пустые браузерные хранилища.

При открытии самого сайта загружаются его локальные шрифты, изображения, скрипты и видео. Эти запросы не содержат введённых условий оплаты.
